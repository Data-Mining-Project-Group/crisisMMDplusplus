CrisisMMD++ Human Verification Survey: Setup
=============================================

What is in this folder
----------------------
site/                    The survey website. Upload ONLY this folder to GitHub.
  index.html             The survey page
  items.json             The 900 tweet-image pairs (labels shown as Option A / Option B only)
  img/                   Created in Step 1 (36 files, 25 images each)
build_images.py          Step 1 script: shrinks and packs the 900 images
image_list.csv           List of images that build_images.py reads
apps_script.gs           Google Sheet backend code (Step 2)
PRIVATE_answer_key.csv   Which option (A or B) was the human label and which was the LLM label,
                         plus stratum info. KEEP PRIVATE. Never upload it to GitHub.

Sample: 900 items (5% of 18,082). 450 (50%) have a human damage-severity label.
  With human damage label: severe 180, mild 135, little/no 105, can't judge 30
  Without human damage label (by LLM severity): little/no 150, severe 150, mild 80, can't judge 70
  Within each group, items are spread across the 7 events in proportion to their size.
  No two items share the same perceptual hash. A/B order is random for each question (seed 15).


Step 1. Build the images (5 minutes, run once)
----------------------------------------------
Open a terminal (or Anaconda Prompt) in this CrisisMMD_Survey folder and run:
    python build_images.py
It needs Pillow (already installed if you use torchvision). It writes site/img/chunk_00.json ... chunk_35.json.


Step 2. Create the Google Sheet backend (10 minutes)
-----------------------------------------------------
1. Go to sheets.google.com and create a blank sheet named "CrisisMMD++ Survey Responses".
2. Click Extensions > Apps Script. Delete the sample code and paste all of apps_script.gs. Click Save.
3. Click Deploy > New deployment. Click the gear icon and choose "Web app".
     Execute as:     Me
     Who has access: Anyone
   Click Deploy and allow the permissions (choose your account > Advanced > Go to project).
4. Copy the Web app URL (it ends with /exec).
5. Open site/index.html in a text editor, find the line
       const SCRIPT_URL = "";
   and paste the URL between the quotes. Save.
Responses appear in the "Responses" tab, one row per item answered.
Note: if you change apps_script.gs later, use Deploy > Manage deployments > Edit > New version,
so the URL stays the same.


Step 3. Publish on GitHub Pages (5 minutes)
-------------------------------------------
1. On github.com click New repository, for example "crisismmd-survey". Public is required for
   free GitHub Pages.
2. Click "uploading an existing file" and drag in everything INSIDE the site folder
   (index.html, items.json and the img folder). About 38 files, so one upload works. Commit.
3. Settings > Pages > Source: "Deploy from a branch", Branch: main, folder: / (root). Save.
4. After 1 to 2 minutes the survey is live at https://<your-username>.github.io/crisismmd-survey/


Step 4. Test before sharing
---------------------------
Open the link, enter a test name such as "test_yasir", answer 2 items, and click End.
Check that 2 rows appear in the Google Sheet, then delete those rows before sharing the link.


How items are handed out
------------------------
Every click on Next gives the rater the item with the fewest responses so far that they have not
already done. An item that someone is working on is held for 15 minutes so two people don't get
the same one at once. The progress bar counts items that have at least one response, out of 900.
After all 900 have one response, raters start getting second responses, which you can use for
inter-rater agreement.


Notes
-----
- Raters should use the same name every time so their answers can be grouped.
- The images come from CrisisMMD v2.0. Hosting them on a public page should follow the dataset's
  redistribution terms, so check with Dr. Adesokan before sharing the link widely.
- For analysis, join the Responses sheet with PRIVATE_answer_key.csv on item_id, then map each
  A/B choice to human or LLM with img_A_source, txt_A_source and sev_A_source.
